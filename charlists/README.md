# 字表来源

`test/build-hanzi-packs.js` 用这两份字表决定内置哪些字的笔顺数据、按什么顺序切分包。

| 文件 | 内容 | 出处 | 是否内置 |
|---|---|---|---|
| `guobiao-2013-ji1.txt` | 一级字 3500 个（常用） | 《通用规范汉字表》（2013 年） | ✅ |
| `guobiao-2013-ji2.txt` | 二级字 3000 个（**人名地名用字**） | 同上 | ✅ |
| `guobiao-2013-ji3.txt` | 三级字 1605 个（生僻） | 同上 | ❌ 见下 |
| `kebiao-2022-biao1.txt` | 常用字 2500 个 | 《义务教育语文课程标准（2022 年版）》附录 5 字表一 | ❌ 已被国标一级覆盖 |
| `kebiao-2022-biao2.txt` | 次常用字 1000 个 | 同上，字表二 | ❌ |
| `_no-stroke-data.txt` | 国标一二级里数据源没收录的 129 字（自动生成） | — | — |

**当前打包的是国标一级 + 二级共 6500 字**（实收 6371，其余 129 个数据源本身没有）。

为什么收到二级为止：家长最容易碰壁的是给孩子名字做字帖，而人名用字
（劼、昶、珩、祎、骁、琛、奕、烨、瑄…）**几乎全部落在二级**。
三级 1605 字里有 1239 个数据源本身就没有，只多 495 个有效字，不划算；
数据源全部 9574 字则要 19.5MB，加上主包离 20MB 上限只剩 70KB，没有余地。

课标那两份字表留着备查：曾经内置的是课标字表一 2500 字，后来发现它解决不了
人名用字才换成国标。两者高度重叠，课标 2500 全在国标一级里。

切包按**字节**贪心而不是按字数等分——生僻字的路径明显更长，
按字数切会让某些包鼓到 1.9MB 顶着 2MB 上限。

全部抄录自 [zispace/hanzi-chars](https://github.com/zispace/hanzi-chars) 的 `data-charlist/`，
格式原样保留：`#` 开头是注释，其余每行一个字。

排序是一级在前、二级在后：一级是日常用字，让它们集中在前面的包里，
多数人只会触发下载前一两个包。
